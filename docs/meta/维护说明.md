[在 My Project 中编辑](https://chatgpt.com/space/page_8e0badc08fec8191aeea02f2f78156d4)

> 内容版本：**v0.0.3**；编辑规范已于 **2026-10-16** 按作者手工修订提交 `faf89e0` 同步。历史结构变化见“版本记录”，当前写法以[文档维护规则](%E6%96%87%E6%A1%A3%E7%BB%B4%E6%8A%A4%E8%A7%84%E5%88%99.md)为准。

本目录是把散落在 `raw/`（metree / notion / vvdworld 三平台导出）与 `pixcel/`（图片池）中的**原创虚构世界观设定**整理为规范化 wiki 条目的成果。

- **原始资料一律不动**：`raw/` 与 `pixcel/` 是只读归档；`wiki/` 是唯一工作区。

- **整理原则**：忠实资料，直接、充分地介绍设定，链接互通。正文使用连贯叙述，表格、列表和交叉链接按内容需要保留；取消固定三栏目与机械关联列表。有实质内容时可设“考据”“作者谈”，编务记录不写回读者条目；必要的冲突与版本核对集中登记在[待决问题与冲突清单](%E5%BE%85%E5%86%B3%E9%97%AE%E9%A2%98%E4%B8%8E%E5%86%B2%E7%AA%81%E6%B8%85%E5%8D%95.md)或任务报告。

- **图片**：仅登记索引（`图片素材索引.md` 尚未建立），未复制挂载（作者答复：所有任务均不处理图片素材）。

- **本目录定位**：`meta/` 存放面向编辑者的元信息与规范文本，不属于 `wiki/` 读者向内容。现含五份文档（`维护说明.md`、`术语规范与别名对照.md`、`待决问题与冲突清单.md`、`文档维护规则.md`、`Quartz站点维护说明.md`）与一个子目录 `原始来源导读/`（深度阅读摘要 + 蓝皮书）。

## 写作与维护规范

**首先适用 [文档维护规则](%E6%96%87%E6%A1%A3%E7%BB%B4%E6%8A%A4%E8%A7%84%E5%88%99.md)**——面向智能体编辑者的长期维护规则（raw 内容的收录方式、开发向信息的删除判据、文件命名、frontmatter 约定），与本页或 `wiki/_templates/使用说明.md` 冲突时**以其为准**。

速览（体例细则详见 `wiki/_templates/使用说明.md`）：

1. 条目 = YAML frontmatter（`title/aliases/type/tags/status/canon`）+ 按内容组织的正文；页面头部不设置 `source`，来源定位保留于编辑台账。新条目参考 `wiki/_templates/` 对应模板，删去无内容的字段行、章节与占位提示，不强制相同骨架。

2. 文件名 = 规范名（见[术语规范与别名对照](%E6%9C%AF%E8%AF%AD%E8%A7%84%E8%8C%83%E4%B8%8E%E5%88%AB%E5%90%8D%E5%AF%B9%E7%85%A7.md)）；一个条目一个文件。

3. 链接一律**标准 Markdown 相对链接**（不使用专有双链语法），写作 `[名](相对路径.md)` 形式。

4. `type` 固定词表：角色/组织/地点/历史事件/物品/概念/作品/写作素材；`status`：完整/较完整/草稿/骨架；`canon`：正典/存疑/旧稿/弃稿。

5. 采用作者已明确的设定与手改措辞，直接介绍事实；未决冲突登记[待决清单](%E5%BE%85%E5%86%B3%E9%97%AE%E9%A2%98%E4%B8%8E%E5%86%B2%E7%AA%81%E6%B8%85%E5%8D%95.md)，不自行裁决，不在文末补“词条历史”。

6. 新增条目后同步[总索引](../00-%E5%AF%BC%E8%A7%88%E4%B8%8E%E7%B4%A2%E5%BC%95/%E6%80%BB%E7%B4%A2%E5%BC%95.md)；新别名回填术语表。
